# Kharismart Android POS & Management System: 14-Day Implementation Blueprint

This guide provides a step-by-step roadmap for building the Kharismart application (SRS Revision B) in Android Studio using Jetpack Compose and Room SQLite. Each step contains beginner-friendly explanations ("How-To"), the exact contextual information to paste into an AI chat session, and a prompt designed to generate complete, ready-to-run code.

## Day 1: Database Entities & Constants

### Beginner Method & How-To

- **Concept:** Room is an abstraction layer over SQLite. You define Kotlin `data class` files with annotations like `@Entity`, `@PrimaryKey`, and `@ColumnInfo`. Room automatically translates these into SQLite `CREATE TABLE` statements. Every amount of money is a `Long` (SQLite integers are 64-bit, so sums over months can never overflow).
- **File Location:** In Android Studio's Project pane, expand `app/src/main/java/com/byteall/kharismart/` and create the package `data/local/entity`, plus the file `data/local/Constants.kt`.
- **Goal:** Create the 10 data classes matching the 10 system tables (`users`, `categories`, `products`, `transactions`, `transaction_items`, `stock_movements`, `debts`, `debt_payments`, `finance`, and `settings`) and one constants file. This day only needs to **compile**; the database class comes on Day 2 so that every query can be validated together.

### Context to Give to the AI

```text
(Paste the Master Context & Project Conventions block first.)

We are implementing the 10 SQLite tables for Kharismart (SRS Revision B):
- All primary keys are autoincrement Long integers, except settings (settings_id is fixed to 1).
- Money is Long. Quantities and stock are Int. Booleans are Int (1 = true, 0 = false).
- Dates are ISO strings "yyyy-MM-dd HH:mm:ss" in WIB.
- Foreign keys must enforce onUpdate = ForeignKey.CASCADE, onDelete = ForeignKey.RESTRICT, except where stated.
- Debts has an optional unique foreign key `transaction_id` (null for manual debts, set for POS credit sales). The optional credit due date is stored inside `debts.note` (SRS Table 18), there is no due_date column.

- Every optional settings column (store_address, receipt_footer, qris_bank, qris_owner_name, qris_image, the three targets, backup_folder, last_backup_at) is nullable.
```

## Day 2: DAOs, Password Hasher, Room Database, Triggers & Seed Users

### Beginner Method & How-To

- **Concept:** DAOs (Data Access Objects) contain the SQL queries. `Flow` methods update the UI automatically when the data changes; `suspend` methods do a one-shot read or write. Room only checks every `@Query` when the `@Database` class exists, so the DAOs and the database are built **together** today and you find any SQL mistake immediately.
- **Triggers:** SQLite triggers protect data rules inside the database engine (stock can never go below 0, `settings` can never have a second row). Room cannot declare them with annotations, so they are created in a `RoomDatabase.Callback`.
- **File Location:** `data/local/dao`, `data/local/model` (query result classes), `util/security/PasswordHasher.kt`, `data/local/KharismartDatabase.kt`.
- **Goal:** All 8 DAOs, the database with triggers, and seed data (categories, settings, and the two demo users `sumarti` [admin] and `rizki` [cashier]) so the Lock Screen works on the very first launch.

### Context to Give to the AI
